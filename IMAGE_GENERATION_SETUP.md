# FlavorFusion image generation (Gemini 3.1 Flash Image)

Pollinations has been removed. Cover images are generated by Google's `gemini-3.1-flash-image` model through the Vercel function at `/api/generate-cover`.

## Required Vercel environment variables

Add these under **Vercel → Project → Settings → Environment Variables** for Production (and Preview/Development if needed):

- `GEMINI_API_KEY`: a Gemini API key from Google AI Studio. Server-only; do not use a `VITE_` prefix.
- `FIREBASE_SERVICE_ACCOUNT_JSON`: the complete JSON contents of a Firebase service-account key for the same Firebase project used by the web app. Keep it secret. The service account is used only by the serverless function to verify Firebase Authentication ID tokens.
- `ALLOWED_ORIGINS`: exact allowed website origins, comma-separated. Production default: `https://flavorfusion-ai.vercel.app`. For a Vercel preview deployment, add its exact `https://...vercel.app` origin if you intend to test there.

The existing `VITE_FIREBASE_*` variables remain the Firebase Web App config. They are not substitutes for the Admin service-account JSON.

After adding or changing variables, redeploy the Vercel project.

## Firebase service account

In Firebase Console, open **Project settings → Service accounts → Firebase Admin SDK → Generate new private key**. Put the entire downloaded JSON file contents into the Vercel environment variable `FIREBASE_SERVICE_ACCOUNT_JSON`. Do not commit the key file or paste it into any `VITE_` variable. Ensure the service account belongs to the same Firebase project as `VITE_FIREBASE_PROJECT_ID`.

## Local development

The Vite dev server alone does not execute Vercel Functions. Use the Vercel CLI (`npx vercel dev`) to test `/api/generate-cover` locally, and provide the server-only variables in a local `.env` file (already ignored by Git). For local browser testing, add `http://localhost:3000` or the actual local origin to `ALLOWED_ORIGINS`.

## Security and behaviour

- The Gemini API key never reaches the browser.
- The function requires a valid Firebase ID token and verifies it with Firebase Admin.
- The function accepts POST only, checks allowed origins, validates prompt size, and applies a best-effort per-instance rate limit (8 requests per 10 minutes per IP; serverless instances do not share this in-memory counter).
- Generated image bytes are converted in the browser to a 720×540 JPEG data URL and stored using the existing Firestore `thumbnail` field. No Firebase Storage migration is required.
- Gemini/API errors are returned to the UI. There is no Pollinations or FLUX fallback.
